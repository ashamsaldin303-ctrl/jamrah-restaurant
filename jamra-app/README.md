# جَمرة — Jamrah 🔥 (v4)
مشروع مطعم متكامل بـ **React** — ست صفحات، تصميم سينمائي داكن بجمرات حيّة، وموبايل بمستوى تطبيق أصلي.

## التقنيات
- **Vite 5 + React 18** (JSX, hooks, context)
- **React Router 6** (HashRouter — يعمل حتى من ملف واحد)
- **Framer Motion 11** (كشف سطري، shared-layout للمعرض، ستائر الانتقال، سبرينغات)
- تصميم Data-driven: `src/data/content.js` (القائمة/الأطباق/الآراء/المعرض/الطقوس/المسيرة)

## الموبايل (مدعوم بفحوص Playwright حقيقية)
- شريط تبويبات سفلي بأسلوب التطبيقات (فقاعة حجز مركزية + مؤشر متوهج منزلق)
- safe-area insets، خطوط حقول 16px (منع زوم iOS)، overscroll contain
- snap إلزامي لسلايدر الأطباق، رقاقات أيام شبكية، أهداف لمس ≥44px
- `content-visibility` للأقسام البعيدة + تقليل blur + جمرات أقل = سلاسة
- **ديباج موثق**: أُصلح (١) فيض أفقي كان يُصغّر الصفحة كلها (هالة `.ritual::before`)، (٢) `scrollTo(0,y)` كان يقفز لليسار في RTL، (٣) `background-clip:text` لا يُرسم على أبناء بـ filter (عنوان الهيرو)، (٤) min-content انفجر عبر رقاقات الأيام.

## سجّل تدقيق v4 (فحص بصري حقيقي عبر Playwright)
| العلة | التشخيص | الإصلاح |
|---|---|---|
| تصغير الصفحة كلها على الموبايل (عمود ضيق) | فيض أفقي 55px من هالة `.ritual::before` خارج القص | `overflow:clip` للقسم |
| قصّ أفقي عند التنقل/السكرول | `scrollTo(0,y)` ثنائية الأرجل تقفز لليسار في RTL | صيغة كائن `{top}` في كل المواضع |

| صور سلايدر الأطباق مكسورة | مفاتيح `dish_*` غير موجودة في خريطة IMG | ربط احتياطي للمفاتيح |

| اجتماعيات القائمة المفتوحة خلف شريط التبويبات | ترتيب z/مسافات | إخفاء الشريط مع `body.no-scroll` + إزاحة |

## v5 — هيرو الموبايل + دراسة الـ3D
### هيرو الموبايل الجديد
صورة الطعام أولًا داخل قوسٍ متوهّج (قاعدة جمر مضيئة أسفله)، ميدالية 3D دوّارة، شارة تقييم وختم دائري على حواف القوس، ثم العنوان بكشفٍ كلمي وخط نار، فأزرار بعرض مريح وإحصاءات مضغوطة — تكوين بأسلوب التطبيقات الفاخرة.

### تحليل الـ3D (القرار: لا WebGL — نعم 3D إدراكي)
درسنا إضافة three.js/WebGL ورفضناها لأسباب: +600KB في حزمة الملف الواحد، استهلاك GPU/بطارية على الجوال، غياب أصول طعام 3D بنفس جودة التصوير (الأشكال الأولية ستبدو رخيصة)، وخطر غياب WebGL في بعض WebViews داخل التطبيقات.
البديل المنفَّذ (عمق إدراكي بلا WebGL):
- ميدالية نحاسية تدور بـ CSS-3D (وجهان backface-hidden)
- بطاقات الوصايا تقلب 180° (hover/لمس) بـ preserve-3d
- ميلان perspective حيّ لبطاقات الأطباق
- بارالاكس متعدد الطبقات (خلفية/قوس/شرائح/ميدالية بسرعات مختلفة)
- تكديس منظور لبطاقات الطقوس + تكبير shared-layout للمعرض

## الفحص النهائي العميق (v5-audit)
فحص آلي شامل لكل المسارات (ديسكتوب + iPhone): صفر أخطاء كونسول/صفحة، h1 واحد لكل صفحة، أزرار بلا اسم صفر، تنقل رجوع سليم، Deep-links سليمة.
ما أُصلح/أُضيف نتيجة الفحص:
- **SEO/Social**: وسوم OpenGraph + Twitter Card + JSON-LD (schema.org/Restaurant) في الجذر
- **a11y**: رابط تخطٍّ للمحتوى، إغلاق العارض بـ Escape وتنقّل بالأسهم وSpace على البلاطات، `MotionConfig reducedMotion="user"`، aria-live لعدّاد نتائج القائمة، توسيع مناطق اللمس (t-dot عبر ::after، dish-link بارتفاع 42px)
- **متانة**: ErrorBoundary بواجهة «انطفأت جمرةٌ هنا» تحيط بالمسارات
ملاحظات مقبولة: عنصر 326×28 في الفحص هو رابط هاتف داخل قائمة مغلقة (visibility:hidden — إيجابية كاذبة)، وصور d‌ecorative بـ alt="" تُحتسب فارغةً في الفحص وهي صحيحة وصوليًا.
